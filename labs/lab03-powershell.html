Lab 03: Manage Users and Groups with Microsoft Graph PowerShell

Script Microsoft Entra ID the way admins do: connect with only the scopes you need, find the right cmdlet, query users, and create a security group.

VS Code · PowerShell 7Intermediate~15 min

Scenario and Objectives

You're an Entra ID admin who needs a repeatable way to report on accounts and set up project groups. You script it with Microsoft Graph PowerShell instead of clicking through the portal.

  • Install only the Microsoft Graph PowerShell modules you need.
  • Connect with explicit delegated scopes and inspect the session.
  • Discover cmdlets and permissions with Find-MgGraphCommand and Find-MgGraphPermission.
  • Query users, including an advanced query, then create and populate a security group.
  • Call any REST endpoint with Invoke-MgGraphRequest.
Related topic: Microsoft Graph PowerShell · Advanced Queries

You sign in as yourself. Each cmdlet becomes a Microsoft Graph REST call with your delegated token.

Prerequisites and Names

  • PowerShell 7 or later (recommended), and VS Code with the PowerShell extension.
  • A test-tenant admin account that can consent to User.Read.All and Group.ReadWrite.All (both need admin consent).
  • Optional, for the stretch goal: the daemon app values from Lab 02.

Build

Open a PowerShell terminal in VS Code (Terminal > New Terminal, then choose pwsh) and run each block in order.

Step 1: Install the Modules

The full Microsoft.Graph module installs dozens of submodules. Install only the three this lab uses.

PowerShell 
$PSVersionTable.PSVersion
Install-Module Microsoft.Graph.Authentication, Microsoft.Graph.Users, Microsoft.Graph.Groups -Scope CurrentUser -Repository PSGallery
Get-InstalledModule Microsoft.Graph.* | Select-Object Name, Version

Expected result: PowerShell 7.x, and the three modules listed with the same version. If prompted about an untrusted repository, answer Y.

Step 2: Connect with Explicit Scopes

PowerShell 
Connect-MgGraph -Scopes "User.Read.All", "Group.ReadWrite.All" -NoWelcome
Get-MgContext | Select-Object Account, AuthType, AppName
(Get-MgContext).Scopes
  1. Sign in with your test-tenant admin account in the window that opens.
  2. On the consent prompt, review the permissions and accept.

Expected result: AuthType is Delegated and the scopes include User.Read.All and Group.ReadWrite.All.

Note: Microsoft Graph PowerShell has no permissions until you ask for them. Request only the scopes the script needs; you can run Connect-MgGraph again with more scopes later.

Step 3: Discover Cmdlets and Permissions

PowerShell 
Find-MgGraphCommand -Uri '/users' -Method GET | Select-Object Command, Module, Method, URI
Find-MgGraphPermission -SearchString 'GroupMember' -PermissionType Delegated

Expected result: Get-MgUser is the cmdlet for GET /users, and the permission search lists GroupMember.Read.All and GroupMember.ReadWrite.All with their consent type.

Step 4: Query Users

PowerShell 
# First page, only the properties you need
Get-MgUser -Top 5 -Property DisplayName, Mail, AccountEnabled |
    Select-Object DisplayName, Mail, AccountEnabled

# -All follows @odata.nextLink for you
(Get-MgUser -All -Property Id | Measure-Object).Count

# Advanced query: 'ne' needs ConsistencyLevel eventual and a count
Get-MgUser -Filter "accountEnabled ne true" -ConsistencyLevel eventual -CountVariable disabledCount -Property DisplayName |
    Select-Object DisplayName
"Disabled accounts: $disabledCount"

Expected result: Five users, the total user count, and the number of disabled accounts (it can be 0).

Step 5: Create a Security Group and Add Yourself

PowerShell 
$suffix = "<suffix>"
$group = New-MgGroup -DisplayName "Graph Workshop $suffix" `
    -MailEnabled:$false -MailNickname "graph-workshop-$suffix" `
    -SecurityEnabled -Description "Created in Lab 03"
$group | Select-Object Id, DisplayName, SecurityEnabled

$me = Get-MgUser -UserId (Get-MgContext).Account
New-MgGroupMember -GroupId $group.Id -DirectoryObjectId $me.Id
Get-MgGroupMember -GroupId $group.Id | ForEach-Object { $_.AdditionalProperties.displayName }

Expected result: The new group's ID and name, then your display name as its only member.

Step 6: Call Raw REST and See the HTTP Traffic

PowerShell 
Invoke-MgGraphRequest -Method GET `
    -Uri "https://graph.microsoft.com/v1.0/groups/$($group.Id)?`$select=displayName,securityEnabled,createdDateTime"

Get-MgGroup -GroupId $group.Id -Property DisplayName -Debug

Expected result: The first command returns the three selected properties as a hashtable. The second prints the full HTTP request and response, showing that each cmdlet is a Microsoft Graph REST call.

Note: The backtick before $select stops PowerShell from treating it as a variable inside the double-quoted string.

Test and Verify

PowerShell 
Get-MgGroup -Filter "displayName eq 'Graph Workshop $suffix'" -Property Id, DisplayName, SecurityEnabled, MailEnabled |
    Select-Object Id, DisplayName, SecurityEnabled, MailEnabled
  • Get-MgContext shows a delegated session with exactly the two scopes you requested.
  • The advanced query returned a count without an error.
  • The group exists with SecurityEnabled True and MailEnabled False.
  • You're the only member of the group.
  • The -Debug output shows a GET to https://graph.microsoft.com/v1.0/groups/....

Stretch Goal: App-Only Session

Connect as the Lab 02 daemon app and see how application permissions change what the session can do.

PowerShell 
$tenantId = "<tenant-id>"
$daemonClientId = "<daemon-client-id>"
$secret = Read-Host "Daemon client secret" -AsSecureString
$cred = [System.Management.Automation.PSCredential]::new($daemonClientId, $secret)

Disconnect-MgGraph | Out-Null
Connect-MgGraph -TenantId $tenantId -ClientSecretCredential $cred -NoWelcome
Get-MgContext | Select-Object AuthType, AppName, Scopes

Get-MgUser -Top 3 -Property DisplayName | Select-Object DisplayName
New-MgGroup -DisplayName "Should fail" -MailEnabled:$false -MailNickname "should-fail" -SecurityEnabled

Expected result: AuthType is AppOnly and Scopes lists User.Read.All. Reading users works; creating a group fails with 403 Authorization_RequestDenied, because the daemon only has User.Read.All.

Troubleshooting

SymptomCheck
The sign-in window doesn't appearIt may be behind VS Code. Or run Connect-MgGraph -Scopes ... -UseDeviceCode and complete sign-in at the URL it prints.
Insufficient privileges to complete the operationThe session lacks a scope. Run (Get-MgContext).Scopes, then reconnect with the missing scope.
Need admin approval at consentSign in with an admin account in your test tenant.
Advanced query fails with Request_UnsupportedQueryInclude both -ConsistencyLevel eventual and -CountVariable.
New-MgGroup fails because the mail nickname existsChoose a different $suffix.
Windows PowerShell 5.1 won't load the modulesUse PowerShell 7, or set the execution policy to RemoteSigned for the current user.

Cleanup and References

Delete the lab group and sign out. If you ran the stretch goal, reconnect with delegated scopes first, because the daemon can't delete groups.

PowerShell 
Connect-MgGraph -Scopes "Group.ReadWrite.All" -NoWelcome
$group = Get-MgGroup -Filter "displayName eq 'Graph Workshop $suffix'"
Remove-MgGroup -GroupId $group.Id
Disconnect-MgGraph

Microsoft Graph PowerShell caches your sign-in across sessions until you run Disconnect-MgGraph. Groups have no cost.
