Lab 01: Explore Microsoft Graph with Graph Explorer

Send real Microsoft Graph requests from your browser, shape the responses, consent to permissions, and read an error, without writing any code.

BrowserBeginner~10 min

Scenario and Objectives

You're about to integrate an app with Microsoft 365 and want to see the real request and response shapes first. You use Graph Explorer to try the requests your app will make.

  • Run a sample query against demo data, then against your own tenant.
  • Shape responses with $select, $filter, and $top, and spot @odata.nextLink.
  • Run an advanced query with ConsistencyLevel: eventual.
  • Consent to a permission and read a Microsoft Graph error response.
  • Find the SDK code for a request.
Related topic: Graph Explorer · Making Requests · Errors and Throttling

Prerequisites and Names

  • A modern browser.
  • A work or school account in a test or developer tenant. A Microsoft 365 E5 developer sandbox from the Microsoft 365 Developer Program works well if you qualify.
  • For Step 5, the ability to consent to User.ReadBasic.All (most users can; your tenant policy decides).
ValueWhere you use it
<your-domain>Your tenant's email domain, for example contoso.onmicrosoft.com (Step 6)
Important: Graph Explorer runs requests against the tenant you sign in to. This lab only reads data, but don't run POST, PATCH, or DELETE requests against a production tenant.

Build

Step 1: Run a Sample Query Without Signing In

  1. Open Graph Explorer (aka.ms/ge).
  2. In the left pane, select the Sample queries tab and choose Get my profile.
  3. Confirm the query box shows GET, v1.0, and https://graph.microsoft.com/v1.0/me, then select Run query.

Expected result: A 200 status and a JSON profile for a sample user appear in Response preview.

Step 2: Sign In to Your Tenant

  1. Select the profile avatar in the top-right corner and sign in with your test-tenant account.
  2. Accept the consent prompt for the basic permissions Graph Explorer requests.
  3. Run Get my profile again.

Expected result: The response now shows your displayName and userPrincipalName.

Step 3: Return Only the Properties You Need

  1. Replace the query with the following URL and select Run query.
GET https://graph.microsoft.com/v1.0/me?$select=displayName,mail,jobTitle,officeLocation
  1. Compare the response with Step 2: only the four selected properties are returned.
  2. Select the Response headers tab and find request-id.
Note: Without $select, some responses include an @microsoft.graph.tips property recommending it. That's Microsoft Graph telling you to ask for less data.

Step 4: Filter and Page Through Users

  1. Run this query:
GET https://graph.microsoft.com/v1.0/users?$select=displayName,mail&$top=3
  1. If you get a 403, continue with Step 5, then come back.
  2. Scroll to the end of the response and find @odata.nextLink. Copy its full value into the query box and run it to get the next page.
  3. Now filter by name:
GET https://graph.microsoft.com/v1.0/users?$filter=startswith(displayName,'A')&$select=displayName,mail

Expected result: Only users whose display name starts with A are returned.

Step 5: Consent to a Permission

  1. Select the Modify permissions tab.
  2. Find User.ReadBasic.All (the least-privileged permission for listing users) and select Consent.
  3. Complete the consent prompt, then run the Step 4 queries again.
Note: Modify permissions lists the permissions that can run the current query. Choose the least-privileged one that works. If you see Need admin approval, your tenant requires an admin to consent.

Step 6: Run an Advanced Query

  1. Run this query, replacing <your-domain>:
GET https://graph.microsoft.com/v1.0/users?$filter=endsWith(mail,'@<your-domain>')&$count=true&$select=displayName,mail
  1. Read the error: the endsWith operator requires advanced query parameters.
  2. Select Request headers, add the key ConsistencyLevel with the value eventual, and run the query again.

Expected result: A 200 response with an @odata.count value and the matching users.

Step 7: Read an Error Response

  1. Remove the ConsistencyLevel header, then run a request for a user that doesn't exist:
GET https://graph.microsoft.com/v1.0/users/00000000-0000-0000-0000-000000000000
  1. In the response, find the HTTP status, error.code, error.message, and innerError.request-id.

Expected result: A 404 with an error object. The code is the value your app should branch on.

Step 8: Get the SDK Code

  1. Run GET https://graph.microsoft.com/v1.0/me?$select=displayName,mail again.
  2. Select the Code snippets tab and switch between C#, Java, and PowerShell.

Expected result: The same request appears as SDK code. You write code like this in Labs 03 to 06.

Test and Verify

  • You ran GET /me against both the sample tenant and your own tenant.
  • $select returned only the properties you asked for.
  • You followed an @odata.nextLink to a second page of users.
  • The endsWith query failed without ConsistencyLevel: eventual and succeeded with it.
  • You can point to error.code and request-id in a 404 response.

Stretch Goals

  • Run GET https://graph.microsoft.com/v1.0/me/memberOf?$select=displayName and compare it with /me/transitiveMemberOf.
  • Open the Resources tab and browse the users resource to discover relationships you haven't used yet.
  • Switch the version dropdown to beta for GET /me and compare the properties returned.

Troubleshooting

SymptomCheck
403 Forbidden with Authorization_RequestDeniedConsent to the permission on Modify permissions (Step 5), then run the query again.
Need admin approval during consentYour tenant restricts user consent. Ask an admin, or use a developer tenant where you're an admin.
Request_UnsupportedQuery for endsWithAdd the ConsistencyLevel: eventual header and $count=true.
Empty value arrayThe filter matched nothing. Check the domain or starting letter, and that users exist in the tenant.
Responses still show sample dataYou aren't signed in. Check the profile avatar.

Cleanup and References

This lab creates no resources and has no cost. Sign out from the profile avatar when you finish. Consenting to Graph Explorer adds it as an enterprise application in your tenant; admins can review or revoke its permissions under Entra ID > Enterprise apps.
