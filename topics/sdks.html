Microsoft Graph SDKs

Strongly typed clients that handle authentication, retries, and paging, so your code focuses on the data instead of the HTTP plumbing.

C# · PowerShell · Python · JavaConcepts~6 min

What the SDKs Add

The Microsoft Graph software development kits (SDKs) are designed to simplify building high-quality, efficient, resilient applications that access Microsoft Graph.

Source: Microsoft Graph SDK overview, Microsoft Learn

Service library

Models and request builders generated from Microsoft Graph metadata. You get IntelliSense for Users, Groups, Me.Messages, and their properties.

Core library

Retry handling, secure redirects, transparent authentication, payload compression, paging through collections, and batch requests.

The credential you pass in supplies tokens; the middleware adds them and retries throttled calls before your code sees an error.

The Same Call in Four Languages

All four snippets send GET /v1.0/users?$select=displayName,mail&$top=5. The shape is the same: navigate to the resource, set query parameters, send.

C# 
var users = await graphClient.Users.GetAsync(config =>
{
    config.QueryParameters.Select = ["displayName", "mail"];
    config.QueryParameters.Top = 5;
});
PowerShell 
Get-MgUser -Top 5 -Property DisplayName, Mail | Select-Object DisplayName, Mail
Python 
query = UsersRequestBuilder.UsersRequestBuilderGetQueryParameters(select=["displayName", "mail"], top=5)
users = await graph_client.users.get(request_configuration=RequestConfiguration(query_parameters=query))
Java 
UserCollectionResponse users = graphClient.users().get(config -> {
    config.queryParameters.select = new String[] {"displayName", "mail"};
    config.queryParameters.top = 5;
});
Tip: Graph Explorer's Code snippets tab and the API reference pages show the SDK code for any request. In PowerShell, Find-MgGraphCommand -Uri '/users' tells you which cmdlet calls a URL and which permissions it needs.

Work with Resources and Data Types

The SDK turns each JSON response into typed objects. A few patterns cover most of what you meet in practice.

PatternWhat you getExample
EntitiesA model class per resource, with nullable propertiesUser, Group, Message, Event, DriveItem
CollectionsA response object with Value and OdataNextLinkUserCollectionResponse
Complex typesNested objects without their own IDItemBody, DateTimeTimeZone, EmailAddress
Dates and enumsNative types instead of stringsDateTimeOffset?, BodyType
Polymorphic resultsA base type whose items are different subtypesGroup members are DirectoryObject: users, groups, devices, and more
Unknown propertiesAnything not in the model lands in a dictionaryAdditionalData
C#: handle mixed member types, or ask only for users 
var members = await graphClient.Groups[groupId].Members.GetAsync();
foreach (var member in members?.Value ?? [])
{
    switch (member)
    {
        case User user:
            Console.WriteLine($"User:   {user.DisplayName} <{user.Mail}>");
            break;
        case Group group:
            Console.WriteLine($"Group:  {group.DisplayName}");
            break;
        case Device device:
            Console.WriteLine($"Device: {device.DisplayName}");
            break;
        default:
            Console.WriteLine($"Other:  {member.OdataType} {member.Id}");
            break;
    }
}

// OData cast: GET /groups/{id}/members/microsoft.graph.user (advanced query)
var users = await graphClient.Groups[groupId].Members.GraphUser.GetAsync(config =>
{
    config.QueryParameters.Count = true;
    config.QueryParameters.Select = ["displayName", "createdDateTime"];
    config.Headers.Add("ConsistencyLevel", "eventual");
});
foreach (var user in users?.Value ?? [])
{
    DateTimeOffset? created = user.CreatedDateTime;
    Console.WriteLine($"{user.DisplayName} created {created:yyyy-MM-dd}");
}
Note: Properties you didn't $select come back as null, not as errors. If a member's details are null except id and @odata.type, your app lacks permission to read that object type.

Microsoft Graph PowerShell

Microsoft Graph PowerShell wraps the entire API as cmdlets such as Get-MgUser and New-MgGroup. The cmdlets are generated from the API schema, so new APIs arrive quickly. It replaces the Azure AD PowerShell and MSOnline modules and is the recommended way to script Microsoft Entra ID.

Works everywhere

PowerShell 7 and later on Windows, macOS, and Linux. Also runs on Windows PowerShell 5.1.

Least privilege by default

Permissions aren't pre-authorized. You ask for scopes with Connect-MgGraph -Scopes and consent once.

Any API

Invoke-MgGraphRequest calls any REST URL, even when no cmdlet exists yet.

Learn more: Microsoft Graph PowerShell SDK overview

Support and Alternatives

  • The SDKs are open-source GitHub projects. Report SDK bugs on the repository's Issues page.
  • Microsoft support covers the Microsoft Graph HTTP request, so capture the request-id and the raw request when you open a case.
  • If you call only a few APIs and want a smaller package, generate a client with Kiota.

Key takeaway

Use an SDK plus an Azure Identity credential. You get typed models, automatic retries, and paging helpers, and the code reads the same in every language.
