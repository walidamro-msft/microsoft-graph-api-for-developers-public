Errors and Throttling

Read an error response, keep your app healthy when Microsoft Graph asks it to slow down, stay within limits shared across the tenant, and see which apps call Microsoft Graph.

ResilienceAdministration~10 min

The Error Response

Errors use standard HTTP status codes plus a JSON body with a single error object.

Example error body 
{
  "error": {
    "code": "Request_ResourceNotFound",
    "message": "Resource '00000000-0000-0000-0000-000000000000' does not exist ...",
    "innerError": {
      "date": "2026-10-06T14:02:11",
      "request-id": "<request-id>",
      "client-request-id": "<client-request-id>"
    }
  }
}

code

Machine-readable. Write your error handling against this value, and against the most specific nested innerError code you understand.

message

For developers only. It isn't localized and can change at any time, so don't parse it and don't show it to end users.

request-id

Correlates your call with Microsoft Graph logs. Log it with every failure.

Status Codes and What to Do

401Unauthorized: token missing or invalidAcquire a fresh token for the right tenant and audience.
403Forbidden: not enough permission or no required licenseAdd and consent the least-privileged permission; check the user's role or license. insufficient_claims means a Conditional Access policy needs to be satisfied.

Throttling

Microsoft Graph limits how many calls a client can make so the service stays available. Limits vary by service and by request type, so writes can be throttled while reads still succeed. When you exceed a limit, Microsoft Graph returns 429 Too Many Requests with a suggested wait time.

Throttled response 
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 10

{
  "error": {
    "code": "TooManyRequests",
    "message": "Please retry again later."
  }
}

Handle it

  • Wait the number of seconds in Retry-After, then retry.
  • If there's no Retry-After, use exponential backoff.
  • Don't retry immediately: throttled calls still count against your usage.

Avoid it

  • Use delta queries and change notifications instead of polling.
  • Request fewer, smaller calls with $select and $filter.
  • Use Microsoft Graph Data Connect for bulk extraction.
Note: The Microsoft Graph SDKs retry throttled requests automatically using Retry-After or exponential backoff. Requests inside a JSON batch are evaluated individually and aren't retried automatically, so retry the failed ones yourself.

Stay Within Tenant Limits

Microsoft Graph checks each request against several limits at once, and the first one reached triggers throttling. Some limits belong to your app alone, but others are shared by every app in the tenant, so one noisy app can slow down all the others.

flowchart LR
    A[Your app] --> AT{{Per app per tenant}}
    B[Other apps] --> T{{Per tenant, all apps}}
    AT --> T
    A --> G{{Per app, all tenants}}
    T --> MG[Microsoft Graph]
    G --> MG
    class A azure
    class B external
    class AT,G warning
    class T danger
    class MG azure

The tenant-wide limit (red) is shared: your app's traffic counts against the same budget as every other app in the tenant.

ScopeExample limit
Per app, across all tenantsGlobal: 130,000 requests per 10 seconds, for any service
Per tenant, all appsMicrosoft Entra ID writes: 18,000 requests per 5 minutes
Per app per tenantMicrosoft Entra ID reads: 3,500 to 8,000 resource units per 10 seconds, depending on tenant size
Per app per mailboxOutlook: 10,000 requests per 10 minutes and four concurrent requests
Note: Limits differ by service and can change. Check service-specific throttling limits for the APIs you call before you size a workload.

Ask for less

  • $filter and $select on every read.
  • Skip $expand unless you need it.
  • Cache data that rarely changes, such as group names or SKUs.

Call less often

  • Replace polling and full scans with delta queries and change notifications.
  • Spread scheduled jobs out instead of starting them all at once.
  • Use Microsoft Graph Data Connect for bulk extraction; it isn't subject to throttling limits.

Batch, but count correctly

  • A JSON batch holds up to 20 requests and saves network round trips.
  • Each request in the batch still counts against limits individually.

Prioritize and watch

  • Send x-ms-throttle-priority: low on background Microsoft Entra ID calls so they're throttled before user-facing ones. Priority doesn't raise the limit.
  • Alert on x-ms-throttle-limit-percentage; it appears once an app uses more than 80% of its limit.
Microsoft Entra ID response headers to log 
x-ms-resource-unit: 2
x-ms-throttle-limit-percentage: 0.9
x-ms-throttle-scope: Tenant_Application/ReadWrite/<app-id>/<tenant-id>

x-ms-throttle-scope appears on throttled responses and tells you which budget ran out: Tenant_Application (your app in this tenant), Tenant (all apps in the tenant), or Application (your app everywhere).

Monitor Which Apps Call Microsoft Graph

Microsoft Graph activity logs record every HTTP request Microsoft Graph processes for your tenant: line-of-business apps, scripts, SDKs, and Microsoft apps. Send them to a Log Analytics workspace to see which apps call Microsoft Graph, how often, and which ones are throttled.

flowchart LR
    APPS[Apps and scripts] --> MG[Microsoft Graph]
    MG --> DS[Diagnostic setting]
    DS --> LA[(Log Analytics)]
    LA --> KQL[KQL queries]
    KQL --> AL([Dashboards and alerts])
    class APPS external
    class MG,DS azure
    class LA data
    class KQL accent
    class AL success

A diagnostic setting streams the MicrosoftGraphActivityLogs category to your workspace.

What You Need

  • A Microsoft Entra ID P1 or P2 license in the tenant.
  • The Security Administrator role (the least-privileged role that can configure diagnostic settings).
  • An Azure subscription with a Log Analytics workspace. Azure Storage and Event Hubs are also supported destinations.

Turn On the Logs

  1. Sign in to the Microsoft Entra admin center as at least a Security Administrator.
  2. Browse to Entra ID > Monitoring & health > Diagnostic settings.
  3. Select + Add diagnostic setting and enter a Diagnostic setting name.
  4. Select the MicrosoftGraphActivityLogs category.
  5. Under Destination Details, select Send to Log Analytics workspace, choose the Subscription and workspace, and select Save.

Most events arrive within 30 minutes; some take up to 2 hours.

Query Usage per App

KQL: requests, failures, and throttling per app (last 24 hours) 
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(1d)
| summarize Requests = count(),
            Failed = countif(ResponseStatusCode >= 400),
            Throttled = countif(ResponseStatusCode == 429)
    by AppId
| top 20 by Requests desc
KQL: peak and average requests per minute per app 
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(1d)
| summarize PerMinute = count() by AppId, bin(TimeGenerated, 1m)
| summarize PeakPerMinute = max(PerMinute), AvgPerMinute = avg(PerMinute) by AppId
| top 20 by PeakPerMinute desc
KQL: request rate over time, one line per app 
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(1d)
| summarize Requests = count() by AppId, bin(TimeGenerated, 10m)
| render timechart

Tip: Turn an AppId into a name by searching for it in Entra ID > Enterprise apps, or with GET /servicePrincipals(appId='<app-id>')?$select=displayName. Then open the app's Permissions page to review what it's allowed to call.
Important: Log volume grows with tenant size. Microsoft estimates about 15 GiB per month in Azure Monitor Logs for 1,000 users and about 1,200 GiB for 100,000 users. Use a workspace transformation or the Basic log plan to reduce cost, and restrict who can read the workspace: request URIs can contain sensitive values.
Note: The logs cover requests made to your tenant only. You can't see what a multitenant app does in other tenants.

Key Takeaway

Key takeaway

Branch on the status code and the error code, log the request-id, and treat 429 and 503 as "wait, then retry". Remember that tenant-wide limits are shared by every app, so filter, cache, and use change tracking, and turn on Microsoft Graph activity logs to see which apps use the budget.
