Security Best Practices

Keep Microsoft Graph apps from becoming the easiest path into your tenant: smallest permissions, strongest credentials, and consent that someone actually reviews.

Developers and Entra ID adminsChecklist~5 min

Least Privilege

Grant the minimum permission the app needs for the operations it performs. Over-privileged apps increase exposure to unintended access, and users are less likely to consent to them.

Read the signed-in user's profileUser.Read (delegated)User.ReadWrite
Show names and emails of colleaguesUser.ReadBasic.All (delegated)User.Read.All

Tip: Prefer delegated permissions whenever they meet the requirement. Application permissions reach every matching resource in the tenant without a user present, which makes them the most privileged choice.
Avoid: Directory.AccessAsUser.All is the highest-privileged delegated permission, Directory.ReadWrite.All is next, and Directory.Read.All is the highest-privileged read-only permission for Microsoft Entra ID. Use them only when no narrower permission works.

Protect App Credentials

Best: no secret to manage

Managed identities for code running on Azure, or federated identity credentials for GitHub Actions, Kubernetes, and other trusted issuers.

Good: certificate

Microsoft recommends a certificate instead of a client secret before you move to production. Store and rotate it in Azure Key Vault.

Development only: client secret

Convenient for local testing and workshops. Maximum lifetime is 24 months; Microsoft recommends less than 12 months.

  • Never hard-code secrets or commit them to source control. Read them from environment variables, a secret store, or Key Vault.
  • Rotate secrets and certificates on a schedule, and monitor repositories for leaked secrets.
  • Leave Allow public client flows disabled unless the app really uses device code or another public client flow.
Learn more: Add and manage app credentials · Best practices for managing secrets

Handle Data Responsibly

  • Request only the properties you use with $select. Less data in transit means less data to protect in logs and caches.
  • Use change notifications or delta queries instead of copying entire datasets on a schedule.
  • Don't log access tokens or full response bodies that contain personal data.
  • Handle 403 responses that carry insufficient_claims: they mean a Conditional Access policy requires the user to satisfy an extra condition, such as MFA.
Learn more: Developer guidance for Microsoft Entra Conditional Access

Govern Consent (Entra ID Admins)

Review before you consent

Only Privileged Role Administrators and Global Administrators can consent to application permissions. Check each request against what the app actually does.

Control user consent

App consent policies decide which delegated permissions users can grant themselves. Even low-impact permissions can be restricted.

Revoke what isn't used

On API permissions, use Revoke admin consent and Remove permission. Delete app registrations you no longer need.

Isolate admin scripting

For high-privilege PowerShell use, register a dedicated app for Microsoft Graph PowerShell and set Assignment required? to Yes so only assigned admins can use it.

Learn more: Manage app consent policies · Use a custom app for Microsoft Graph PowerShell

Checklist

  • Each permission maps to an operation the app performs.
  • Delegated permissions are used wherever a user is present.
  • No Directory.* permissions unless documented and approved.
  • Production apps use a managed identity, federated credential, or certificate, not a client secret.
  • Secrets are short-lived, stored outside source code, and rotated.
  • Admin consent was reviewed, and unused permissions and apps are removed.

Key takeaway

An app registration is an identity with its own access. Give it the smallest permissions, the strongest credential you can, and an owner who reviews it.
