Detailed Training Guide

Module-by-module talk track built from the speaker notes in resources/slides/Microsoft Graph API Fundamentals for .NET Developers.pptx, corrected against current Microsoft Learn.

Trainer-onlyFacilitation guide

Before the Session

  • Confirm every attendee has a test tenant with an admin role that can grant consent to application permissions. This is the most common blocker; resolve it before the day.
  • Microsoft employees aren't eligible for Microsoft 365 Developer Program sandboxes. Plan a different test tenant for internal audiences.
  • Windows attendees doing Lab 05 (Python) must enable long paths (admin) in advance, or use WSL.
  • Lab 06 (Java) attendees need Maven on PATH; the first mvn run downloads dependencies, so warm the cache before the session if the network is slow.
  • Ask attendees to note whether their tenant blocks device code flow with Conditional Access (Lab 04).

What Is Microsoft Graph (Slides 2 to 6)

  • Anchor line: one endpoint, one token, one request model. Show the services image (slide 4) with the core resources table, then the network image and relationship diagram.
  • The deck says "Azure Active Directory": say Microsoft Entra ID throughout.
  • Slide 5 maps to the four capability cards; slide 6 use cases map to the Use Case Scenarios table. Ask the room which row matches their current project, and whether it's delegated or app-only.
  • AI agents (not in the deck): frame it as "context plus tools". Graph API for actions, the Copilot Retrieval API for grounding, and the MCP Server for Enterprise (preview) for natural-language directory queries. Call out the Copilot license requirement for the Copilot APIs.
  • Misconception: "Graph needs an Azure subscription." Only metered APIs do. Standard APIs come with user licenses.
  • Mention Copilot connectors (formerly Graph connectors) and Data Connect only to place them; the workshop is about the API.

Set Up Your Environment (Slides 7 to 8)

  • Send this page as a pre-read. Open the session by asking who has a test tenant and the right role; pair attendees who don't.
  • The deck lists Visual Studio and .NET only; the page adds VS Code, PowerShell 7, Python, and Java for the multi-language labs.

Authentication and Permissions (Slides 9 to 10)

  • Walk the sequence diagram top band (delegated) then bottom band (app-only). Ask: "Which band can read every mailbox?"
  • Stress that delegated effective access is the intersection of app permission and user access.
  • Correct slide 9: you create a credential, and only confidential clients have one.
  • Use the "Grant Graph Permissions" table to preview Lab 02: same page, different tab, different consent.
  • Entra ID admins in the room: point to the consent section and the governance cards on the security page.

Graph Explorer (Slides 11 to 14)

  • Demo live at aka.ms/ge: signed out with sample data first, then signed in to the test tenant.
  • Show /me with and without $select, then the endsWith query without and with ConsistencyLevel. This sets up Lab 01.
  • Walk the tabs: Modify permissions, Access token (paste into a decoder offline), Response headers, Code snippets.
  • Warn that signed-in writes change real data in the tenant.

Making Requests and Errors (Slides 15 to 18)

  • Correct slide 17: PATCH updates; PUT replaces. Write requests are capped at 4 MB.
  • Use the create, update, and delete examples to show status codes: 201 with a body, 204 without.
  • For slide 18, show the error JSON and say: code against error.code, log request-id, never parse message.
  • Throttling: Retry-After first, backoff second, delta queries and change notifications to avoid it.
  • Show the client-side vs. server-side filter cards, then ask: "How many pages does GET /users take in your tenant?"
  • Stress that tenant-wide limits are shared. For Entra ID admins, walk the activity logs setup and the per-app KQL queries; mention the P1/P2 license and Log Analytics cost before anyone turns it on.

SDKs and Security (Slides 19 to 23)

  • The deck is .NET-only; show the "same call in four languages" section to set up Labs 03 to 06.
  • Slide 22 maps to "Work with Resources and Data Types": polymorphic group members and the OData cast.
  • Explain that the SDK retries throttled calls automatically, except inside JSON batches.
  • Close on the security checklist; ask each attendee which permission in their current project they could narrow.

Summary and Resources (Slides 24 to 25)

  • Read one takeaway per module from the summary table, then show the resources cards: aka.ms/graph and aka.ms/ge.
